# Analyze Fabric (fabric.so) source

Fabric (`/Applications/Fabric.app`, ~331 MB) is a note / "second brain" app. We use it as a
reference for **note-editor UX** (OakReader is migrating its own notes to a ProseMirror-family
WYSIWYG). This skill captures how to dig into it and what's already known.

**The crucial structural fact:** Fabric is *not* a native app and is *not* self-contained.
It is a **Next.js + React web app served live from `https://fabric.so`**, wrapped in an
**Electron** shell generated by **ToDesktop** ("desktopify"). The local `.app` is just the
wrapper; the real UI ships as hashed JS chunks from the CDN. This is the opposite of Dia
(native Swift + bundled Bun source maps) — see [[dia-source-analysis]] for that contrast.

## Golden rules

- **Read-only, on the user's own machine, for research.** Proprietary code shipped to the
  user. Use it to *understand and learn*, never to copy/redistribute verbatim or ship lifted
  code. State this caveat when sharing recovered source.
- **The `_next/static/chunks/*.js` are public assets.** Fetch them directly from `fabric.so`
  with `curl --compressed` — this is the cleanest recovery path and needs no auth. The app's
  *authenticated* surface (your notes, the API JSON) only lives in the local HTTP cache.
- **Build hashes rotate on every deploy.** Chunk filenames (`1101-<hash>.js`) and the Next.js
  build id change constantly. Never hardcode a hash — always re-derive the current list from
  the HTML or the on-disk cache (step 1) before fetching.
- **Verify before trusting old findings.** Facts below are version-stamped. ToDesktop
  auto-updates the shell (Squirrel) and `fabric.so` redeploys the web app independently.
  Re-read the version (step 0) first; treat mismatches as "re-derive from scratch."
- **Two layers, two recoverability tiers:** the **renderer** (note editor, the part we care
  about) is fully recoverable as minified-but-readable JS; the **Electron main process**
  (`main.js`, 3.8 MB) is the ToDesktop wrapper — readable but mostly boilerplate, with
  Fabric's native bits being thin glue over `@todesktop/plugin-*`.

## Established facts (as of Fabric 0.2.10 / ToDesktop desktopify 6.29.0 — RE-VERIFY)

`CFBundleShortVersionString` 0.2.10, bundle id `com.todesktop.220930m1ahpjvoh`,
Electron 38.2.0, desktopifyServerVersion 1.615.2. Renderer origin `https://fabric.so`
(confirmed by `IndexedDB/https_fabric.so_0.indexeddb.leveldb`). Loaded via an `app://`
custom scheme that ToDesktop maps onto the cached/served web app.

### Note editor (the part that matters for OakReader)
- **Editor = Tiptap (ProseMirror).** Fingerprints in the chunks: `@tiptap/extension-undo-redo`,
  `@tiptap/extension-collaboration`, `prosemirror-model`, `createEditor`, `toggleMark`,
  `schema.nodes`, `EditorState`. Plus custom `prosemirror-dropcursor-inline` /
  `prosemirror-dropcursor-block` (block drag-and-drop cursors).
- **Schema** (from `name:"…"` registrations):
  - *Nodes:* `paragraph`, `heading`, `text`, `bulletList`/`orderedList`/`listItem`,
    `taskList`/`taskItem` (checkboxes), `table`, `codeBlock`, `blockquote`, `horizontalRule`,
    `hardBreak`, `image`, `link`, `html`, `placeholder`, `trailingNode` (always-empty last
    block so you can click below content).
  - *Marks:* `bold`, `italic`, `underline`, `strike`, `code`, `highlight`, `link`.
  - *Extensions:* **slash command menu** (ProseMirror `Suggestion`), `wwwAutolink`
    (auto-linkify typed URLs), `undoRedo`, `collaboration`.
  - *Shortcuts:* standard `Mod-b/i/u`, `Mod-e` (code), `Mod-Shift-h` (highlight),
    `Mod-Shift-s` (strike), `Mod-Alt-c` (code block), `Mod-z`/`Mod-y`.
- **Real-time collaboration = Liveblocks + Yjs.** `@liveblocks/client`, `@liveblocks/react`,
  `@liveblocks/zustand`, Yjs `XmlFragment`/`ydoc`, `@tiptap/extension-collaboration`. Notes
  ("notepads") are **CRDT documents**; their state is fetched/persisted at
  `GET/PUT api.fabric.so/v2/notepads/{id}/state` and synced live over a WebSocket
  (`api.fabric.so/socket`). This is the big architectural bet: notes are collaborative,
  multiplayer, offline-mergeable by construction.
- **State management = zustand** (bound to Liveblocks via `@liveblocks/zustand`).
- **Inline AI** in editor: autocomplete/ghost-text hooks present; chat backed by
  `api.fabric.so/v2/chatbot/{models,prompts}`.

### Other renderer facts
- **Canvas / spatial view = tldraw 4.5.10** (`@tldraw/*`, fonts from `cdn.tldraw.com/4.5.10`).
  Fabric has a whiteboard/canvas surface alongside linear notes.
- **Animations = Rive** (`@rive-app/canvas`, `rive.wasm` from unpkg). Onboarding/empty-state art.
- Billing **Stripe**, in-app notifications **Knock** (`api.knock.app`), asset CDN `cdn.fabric.so`.

### Native (Electron / ToDesktop) layer
- Wrapper = ToDesktop. Native capability via `@todesktop/plugin-*`: `active-win`,
  `comm-server`, `exec`, `fs`, `get-app-icon`, `ipc`, `selected-text`.
- **Global quick-capture overlay:** `main.js` has `globalShortcut` (9 refs), `Overlay`
  (8 refs), `alwaysOnTop` (5 refs) → an always-on-top HUD window summoned by a global hotkey
  for capture-from-anywhere. `selected-text` plugin → act on text selected in *any* app
  (save to Fabric / ask AI). Windows ships `FabricOverlaySetupV2.msi`; macOS ships
  `FabricSync.pkg` (a sync/file-watch helper installed outside the sandbox).

### Backend data model (from cached API calls — see step 1)
`api.fabric.so/v2/…`: `user/me`, `user/preferences`, `workspace`, `workspace/member`,
`resource-roots`, `resources/{id}` (+ `/assets`, `/comments`, `/permissions`, `/share-token`),
`resources-activity-log`, `notepads/{id}/state`, `tags`, `tasks`, `integrations`,
`subscription`, `chatbot/{models,prompts}`, `announcement`, `version`, `socket` (WS). The
core noun is a **resource** (anything you save — page, file, clip, note); a **notepad** is the
collaborative note document; sharing is per-resource (`permissions` + `share-token`).

## Bundle / on-disk map

| Path | What |
|---|---|
| `/Applications/Fabric.app/Contents/Resources/app.asar` (74 MB) | ToDesktop wrapper: `main.js` (3.8 MB Electron main), `preload.js` (267 KB), `todesktop.json`, proto files |
| `app.asar` → `package.json` | reveals `@todesktop/plugin-*`, electron 38.2.0, desktopify versions |
| `app.asar.unpacked/`, `files/` | native helpers: `FabricSync.pkg`, `FabricOverlaySetupV2.msi` |
| `Contents/Frameworks/` | Electron Framework + Squirrel (updater) + 4 Helper apps |
| `~/Library/Application Support/Fabric/Cache/Cache_Data` | **HTTP cache** — every URL the app fetched: JS chunks (brotli) + authenticated API JSON |
| `~/Library/Application Support/Fabric/IndexedDB/https_fabric.so_*` | client DB — confirms origin, holds offline note/Yjs state |
| `~/Library/Application Support/Fabric/Local Storage/leveldb` | auth tokens, flags |
| `https://fabric.so/_next/static/chunks/*.js` | **the renderer** — public, fetch clean with curl |

## Procedure

### 0. Identify version (always first)
```bash
/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" /Applications/Fabric.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c "Print :CFBundleIdentifier"        /Applications/Fabric.app/Contents/Info.plist
# wrapper provenance:
python3 -c "import json;d=json.load(open('/tmp/fabric-src/package.json'));print(d.get('electronVersion'),d.get('desktopifyVersion'))" 2>/dev/null
```

### 1. Inventory what the app actually loaded (HTTP cache)
Decompress the on-disk cache to get a size-sorted list of every URL (JS chunks + the
authenticated `api.fabric.so` JSON, which reveals the data model). `pip install brotli` first.
```bash
python3 agent/skills/fabric-source-analysis/scripts/extract-cache.py \
  "$HOME/Library/Application Support/Fabric/Cache/Cache_Data" /tmp/fab-cache-out
sort -rn /tmp/fab-cache-out/_INDEX.txt | head -40          # biggest assets = app chunks
grep -oE "https://api\.fabric\.so/[a-zA-Z0-9/_-]+" /tmp/fab-cache-out/_INDEX.txt | sort -u
```
Note: the extractor reliably recovers the **URL index** and identity-encoded bodies (API
JSON). Brotli-encoded JS often won't cleanly decode from the cache's framing — fetch those
clean in step 2 instead.

### 2. Recover the renderer (the big win) — fetch clean JS from the CDN
The chunk URLs from step 1 are public. `curl --compressed` decodes br/gzip automatically:
```bash
mkdir -p /tmp/fab-js && cd /tmp/fab-js
curl -s --compressed -O "https://fabric.so/_next/static/chunks/1101-<hash>.js"   # use a CURRENT hash
file -b 1101-*.js     # must say "ASCII/UTF-8 text" and grep -c function in the thousands
```
To get a fresh, complete chunk list without the cache, fetch the app HTML / `_buildManifest.js`
and scrape `_next/static/chunks/…\.js`. The editor lives in the largest non-vendor chunks
(in 0.2.10 these were `1101-*`, `330-*`, `6790-*`, `6873-*`).

### 3. Fingerprint the editor + libs
```bash
cd /tmp/fab-js
for kw in prosemirror @tiptap/ toggleMark schema.nodes 'name:"taskItem"' \
          liveblocks yjs XmlFragment '@liveblocks/zustand' tldraw zustand; do
  echo "$kw : $(grep -laE "$kw" *.js | wc -l)"; done
grep -rhoE '@tiptap/[a-z-]+'   *.js | sort | uniq -c | sort -rn   # extension set
grep -rhoE 'name:"[a-zA-Z][a-zA-Z0-9_]{2,30}"' *.js | sort | uniq -c | sort -rn | head -50  # schema
grep -rhoE '"Mod-[A-Za-z-]+"' *.js | sort | uniq -c | sort -rn    # keymap
```

### 4. Native shell (Electron main) — capability surface
```bash
cd /tmp && rm -rf fabric-src && npx --yes @electron/asar extract \
  /Applications/Fabric.app/Contents/Resources/app.asar /tmp/fabric-src
cat /tmp/fabric-src/package.json                       # @todesktop/plugin-* = native powers
grep -aoiE "globalShortcut|alwaysOnTop|Overlay|getSelectedText|selected-text" /tmp/fabric-src/main.js | sort | uniq -c
```
`main.js` is minified ToDesktop boilerplate; don't expect Fabric product logic here — the
interesting native behaviors are the **overlay window**, **global hotkey**, and
**selected-text** capture wired through the ToDesktop plugins.

## Relevance to OakReader

OakReader's note editor is **Milkdown Crepe 7.21 (also ProseMirror-family) in a WKWebView**
(`packages/OakEditor`, `web/src/main.ts`), markdown-as-source-of-truth, single-user, notes
stored as `~/OakReader/notes/{id}.md` + a GRDB `notes` table. So Fabric is an unusually direct
reference: same editor *family* (ProseMirror), different bets.

What's genuinely worth borrowing vs. not:
- **Borrow (cheap, high-value):** slash-command menu UX, `trailingNode` (click-below-to-type),
  `wwwAutolink`, a richer mark set (highlight), `taskList`/`taskItem` polish, and tldraw-style
  block drag handles. All are ProseMirror plugins that port conceptually to Milkdown.
- **Consider (medium):** Fabric's "everything is a *resource*, a note is a *notepad*" model
  maps onto OakReader's `resources`/attachment library — useful framing for unifying notes
  with clips/PDFs and per-item sharing.
- **Probably don't:** Liveblocks+Yjs real-time collab. It's the heaviest piece (CRDT, a WS
  backend, a paid vendor) and OakReader is a local single-user reader. Markdown-on-disk is the
  right tradeoff; only revisit Yjs if multiplayer notes become a product goal. Likewise tldraw
  canvas is a whole second surface — only if a spatial mode is wanted.
- **Note the architectural mirror:** Fabric ships the renderer from a server (always-online,
  instant deploys, but no offline-first guarantee beyond the cache); OakReader bundles its
  editor locally (offline-first, but redeploys require an app update). Don't copy Fabric's
  server-rendered model — OakReader's bundled-WKWebView approach is correct for a local app.
